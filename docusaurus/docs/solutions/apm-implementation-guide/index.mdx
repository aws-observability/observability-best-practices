# APM Implementation Guide: Application Signals and Transaction Search

## Overview

  <div className="omni-hero-frame">

This guide is the entry point to the APM implementation deep dive for [Amazon CloudWatch Application Signals](https://docs.aws.amazon.com/AmazonCloudWatch/latest/monitoring/CloudWatch-Application-Monitoring-Sections.html) with [Transaction Search](https://docs.aws.amazon.com/AmazonCloudWatch/latest/monitoring/CloudWatch-Transaction-Search.html). It covers the architecture, the instrumentation and collector options, and the sampling decisions that control cost and accuracy.

Application Signals gives you service-level health out of the box: auto-discovered services, an application map, and RED (rate, errors, duration) metrics for every operation. Transaction Search stores complete span data in CloudWatch Logs in OpenTelemetry format, so you can query every transaction and apply Logs Insights, metric filters, and subscription filters to span data.

The guide also explains why teams on traditional AWS X-Ray sampling should move to this model. X-Ray SDKs and the X-Ray daemon entered maintenance mode on February 25, 2026, and receive security fixes only.

## Guidance

Application Signals supports five combinations of SDK and collector. Step through them to see who each one suits, what it delivers, and the trade-off you accept.

### Pick your path

<Tabs>
  <TabItem value="fresh" label="Starting fresh" default>

1. Check [prerequisites, permissions, and supported systems](/apm/pages/deep-dive/setup/#prerequisites--permissions).
2. [Enable Application Signals](https://docs.aws.amazon.com/AmazonCloudWatch/latest/monitoring/CloudWatch-Application-Signals-Enable.html) and [Transaction Search](https://docs.aws.amazon.com/AmazonCloudWatch/latest/monitoring/Enable-TransactionSearch.html) in your account.
3. Choose an instrumentation setup. For most AWS-native workloads, start with **ADOT SDK + CloudWatch agent**.
4. Set your [sampling and trace indexing](/apm/pages/deep-dive/setup/#step-4-understanding-sampling-and-trace-indexing) rates, then verify services appear in the Application Signals console.

  </TabItem>
  <TabItem value="xray" label="Migrating from X-Ray">

1. Read [why to migrate](/apm/pages/deep-dive/why-migrate-from-xray/) to compare the X-Ray architecture with Application Signals and Transaction Search.
2. Enable Transaction Search so complete span data lands in CloudWatch Logs.
3. Replace the X-Ray SDK with the ADOT SDK and the X-Ray daemon with the CloudWatch agent. Your existing X-Ray sampling rules keep working.
4. Follow the [X-Ray to OpenTelemetry migration guide](https://docs.aws.amazon.com/xray/latest/devguide/xray-sdk-migration.html) for language-specific changes.

  </TabItem>
</Tabs>

**Why it matters:** both paths end at the same place, OpenTelemetry instrumentation with complete span capture, but the order of steps differs. Starting fresh is a configuration task. Migrating is a code change, so plan it service by service.

### How the telemetry flows

<figure className="omni-hero" style={{float: 'none', width: '100%', maxWidth: 'none', margin: '8px 0 28px'}}>
  <div className="omni-hero-frame">
    <img
      src={require('@site/docs/images/apm-implementation-guide/telemetry-flow.png').default}
      alt="Telemetry flow: the application and ADOT SDK send RED metrics and traces to the CloudWatch agent, which writes metrics as EMF logs to CloudWatch Logs and sends traces to the X-Ray OTLP endpoint; Application Signals and Transaction Search read from CloudWatch Logs, and a percentage of spans is indexed as X-Ray trace summaries"
    />
  </div>
  <figcaption className="omni-hero-caption">
    ADOT SDK + CloudWatch agent: RED metrics and traces land in CloudWatch Logs, and a configurable share of spans becomes X-Ray trace summaries.
  </figcaption>
</figure>

Request sampling and trace indexing are separate controls. Sampling decides which requests are sent to AWS. Indexing decides what share of those spans also becomes X-Ray trace summaries for debugging. Keep indexing low, since the first 1% is included at no extra charge, and use sampling to manage volume.
