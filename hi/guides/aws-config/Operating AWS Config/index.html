AWS Config का संचालन

सभी खातों में सभी क्षेत्रों में AWS Config सक्षम करें​

कई AWS खाते चलाने वाले ग्राहकों के लिए, हम अनुशंसा करते हैं कि AWS Config को आपके संपूर्ण ऑर्गनाइज़ेशन में लागू करें। AWS Config एक क्षेत्र-विशिष्ट सेवा है, इसलिए आपको इसे प्रत्येक उस क्षेत्र में सक्षम करना होगा जहाँ आप संसाधन कॉन्फ़िगरेशन परिवर्तनों और अनुपालन मूल्यांकन को ट्रैक करना चाहते हैं। आप ऐसा तीन तरीकों से कर सकते हैं:

  1. CloudFormation StackSets का उपयोग: CloudFormation StackSets कई क्षेत्रों और खातों में एक साथ AWS Config सक्षम करने, आपके ऑर्गनाइज़ेशन में configuration recorder तैनात करने, और सभी खातों में लगातार सेटिंग्स बनाए रखने के लिए पूर्व-निर्मित टेम्पलेट प्रदान करता है। CloudFormation का उपयोग करके अपने ऑर्गनाइज़ेशन में AWS Config तैनात करने के लिए, कृपया इस ब्लॉग का पालन करें।
  2. AWS Systems Manager Quick Setup का उपयोग: AWS Systems Manager Quick Setup आपके संपूर्ण ऑर्गनाइज़ेशन में Config recorder सक्षम करने का एक सुव्यवस्थित तरीका प्रदान करता है। Systems Manager Quick Setup का उपयोग करके अपने ऑर्गनाइज़ेशन में AWS Config तैनात करने के लिए, कृपया इस ब्लॉग का पालन करें।
  3. AWS Control Tower: AWS Control Tower एक केंद्रीय स्थान से कई AWS खातों को सुरक्षित रूप से सेट अप और प्रबंधित करने में आपकी मदद करता है। सक्षम होने पर, Control Tower स्वचालित रूप से सभी नामांकित खातों में AWS Config को सक्रिय करता है। AWS Control Tower के साथ शुरू करने के लिए, कृपया AWS Control Tower Getting Started सार्वजनिक दस्तावेज़ देखें।

AWS Config recorder सेटिंग्स​

AWS Config recorder सेटिंग्स कॉन्फ़िगर करते समय, एक महत्वपूर्ण बेस्ट प्रैक्टिस यह है कि सभी संसाधन प्रकारों के लिए ट्रैकिंग सक्षम करें। सभी संसाधनों को सक्षम करने का अतिरिक्त लाभ यह है कि Config ट्रैकिंग के लिए उपलब्ध होने पर नई AWS सेवाओं के संसाधन प्रकारों का स्वचालित समावेश होता है, जो बिना मैनुअल हस्तक्षेप के यह सुनिश्चित करता है कि आपका कॉन्फ़िगरेशन प्रबंधन वर्तमान रहे। Global resources के संबंध में, जैसे IAM, केवल एक क्षेत्र में रिकॉर्डिंग सक्षम करना महत्वपूर्ण है (AWS Config को ग्राहक के होम या मुख्य क्षेत्र में सक्षम किया जाना चाहिए)। यह कॉन्फ़िगरेशन दो उद्देश्यों को पूरा करता है: यह डुप्लीकेट configuration items को रोकता है और अनावश्यक लागतों से बचने में मदद करता है। यदि आप कई क्षेत्रों में global resource recording सक्षम करते हैं, तो आपको अनावश्यक कॉन्फ़िगरेशन ट्रैकिंग का सामना करना पड़ेगा और एक ही global resources की कई बार निगरानी के लिए अतिरिक्त खर्च उठाना पड़ेगा। उदाहरण के लिए, IAM users, roles, और policies को ट्रैक करते समय, आपको global resource recording के लिए एक प्राथमिक क्षेत्र (जैसे us-east-1) नामित करना चाहिए और अन्य सभी क्षेत्रों में इस सुविधा को अक्षम करना चाहिए।

Delivery Method बेस्ट प्रैक्टिसएँ​

AWS कॉन्फ़िगरेशन प्रबंधन लागू करते समय, configuration items के लिए उचित delivery methods स्थापित करना महत्वपूर्ण है। एक अनुशंसित बेस्ट प्रैक्टिस यह है कि एक केंद्रीय खाते के भीतर एक केंद्रीकृत Amazon S3 bucket निर्दिष्ट करें, जो एक लॉगिंग खाता या अन्य विशेष रूप से निर्दिष्ट खाता हो सकता है। यह केंद्रीकरण configuration item लॉग के बेहतर ऑर्गनाइज़ेशन और प्रबंधन की अनुमति देता है। बकेट के भीतर स्पष्ट ऑर्गनाइज़ेशन बनाए रखने के लिए, एक संरचित prefix प्रणाली लागू करने की सलाह दी जाती है जो प्रत्येक configuration item के लिए स्रोत खाता और क्षेत्र को स्पष्ट रूप से पहचानती है। कृपया S3 bucket के लिए सुरक्षा बेस्ट प्रैक्टिसएँ भी लागू करें जैसे: ट्रांज़िट और आराम में एन्क्रिप्शन सक्षम करना, सार्वजनिक पहुँच अक्षम करना, और सख्त पहुँच नियंत्रण बनाए रखना। ये सुरक्षा उपाय डेटा सुरक्षा मानकों के अनुपालन को सुनिश्चित करते हैं और सुरक्षा जोखिमों को कम करते हैं।

आप कॉन्फ़िगरेशन परिवर्तनों और अनुपालन स्थिति अपडेट को एक निर्दिष्ट SNS topic पर स्वचालित रूप से स्ट्रीम करने के लिए AWS Config कॉन्फ़िगर कर सकते हैं। कई AWS खातों वाले एंटरप्राइज़ एनवायरनमेंट के लिए, आप इन सूचनाओं को समेकित करने के लिए एक केंद्रीय SNS topic स्थापित करें। यह केंद्रीकृत दृष्टिकोण IT और सुरक्षा टीमों को ऑर्गनाइज़ेशन भर में कॉन्फ़िगरेशन परिवर्तनों की कुशलतापूर्वक निगरानी करने और प्रतिक्रिया देने में सक्षम बनाता है। ऐसा करने के लिए, कृपया इस दस्तावेज़ का पालन करें।

AWS Config के लिए Delegated Admin​

AWS Config के लिए एक delegated administrator एक AWS ऑर्गनाइज़ेशन के भीतर एक निर्दिष्ट सदस्य खाता है जो संपूर्ण ऑर्गनाइज़ेशन में कॉन्फ़िगरेशन सेटिंग्स प्रबंधित करने की अनुमतियाँ प्राप्त करता है। यह administrator AWS Config नियमों को तैनात और प्रबंधित कर सकता है, conformance packs को संभाल सकता है, और कई खातों से कॉन्फ़िगरेशन डेटा एग्रीगेट कर सकता है। उनके पास ऑर्गनाइज़ेशन भर में संसाधन कॉन्फ़िगरेशन और अनुपालन स्थिति में दृश्यता होती है, जो केंद्रीकृत प्रबंधन और निगरानी को सक्षम बनाती है। AWS Config संचालन और एग्रीगेशन के लिए delegated admin का उपयोग करने के लिए कृपया इस ब्लॉग का पालन करें।

AWS Config के लिए delegated administrator का उपयोग एक बेस्ट प्रैक्टिस है क्योंकि यह management account की सुरक्षा करता है, इसके उपयोग को केवल आवश्यक ऑर्गनाइज़ेशनात्मक कार्यों तक सीमित करते हुए AWS Config विशिष्ट प्रशासनिक कर्तव्यों को नामित सदस्य खातों को सौंपता है। यह दृष्टिकोण न्यूनतम विशेषाधिकार के सिद्धांत का पालन करता है, सुरक्षा जोखिमों को कम करता है, और नामित खातों में Config प्रबंधन को केंद्रीकृत करके बेहतर परिचालन नियंत्रण प्रदान करता है।
