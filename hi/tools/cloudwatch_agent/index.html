CloudWatch एजेंट

CloudWatch agent डिप्लॉय करना​

CloudWatch agent को एक इंस्टॉलेशन के रूप में, डिस्ट्रीब्यूटेड कॉन्फ़िगरेशन फ़ाइल का उपयोग करके, कई कॉन्फ़िगरेशन फ़ाइलों को लेयर करके, और पूरी तरह से स्वचालन के माध्यम से डिप्लॉय किया जा सकता है। कौन सा दृष्टिकोण आपके लिए उपयुक्त है यह आपकी आवश्यकताओं पर निर्भर करता है। 1

जानकारी

Windows और Linux होस्ट दोनों पर डिप्लॉयमेंट में Systems Manager Parameter Store में अपने कॉन्फ़िगरेशन संग्रहीत और पुनर्प्राप्त करने की क्षमता होती है। इस स्वचालित तंत्र के माध्यम से CloudWatch agent कॉन्फ़िगरेशन का डिप्लॉयमेंट एक बेस्ट प्रैक्टिस है।

सुझाव

वैकल्पिक रूप से, CloudWatch agent की कॉन्फ़िगरेशन फ़ाइलों को आपकी पसंद के स्वचालन टूल (Ansible, Puppet, आदि) के माध्यम से डिप्लॉय किया जा सकता है। Systems Manager Parameter Store का उपयोग आवश्यक नहीं है, हालाँकि यह प्रबंधन को सरल बनाता है।

AWS के बाहर डिप्लॉयमेंट​

CloudWatch agent का उपयोग AWS के अंदर तक सीमित नहीं है, और यह ऑन-प्रिमाइसेस और अन्य क्लाउड एनवायरनमेंट दोनों में समर्थित है। हालाँकि AWS के बाहर CloudWatch agent का उपयोग करते समय दो अतिरिक्त बातों का ध्यान रखना होगा:

  1. Agent को आवश्यक API कॉल करने की अनुमति देने के लिए IAM क्रेडेंशियल2 सेट अप करना। EC2 में भी CloudWatch API तक अप्रमाणित पहुँच नहीं है3।
  2. यह सुनिश्चित करना कि agent की CloudWatch, CloudWatch Logs, और अन्य AWS endpoints4 तक कनेक्टिविटी एक ऐसे रूट का उपयोग करके है जो आपकी आवश्यकताओं को पूरा करता है। यह इंटरनेट के माध्यम से, AWS Direct Connect का उपयोग करके, या प्राइवेट endpoint (आम तौर पर VPC endpoint कहा जाता है) के माध्यम से हो सकता है।
जानकारी

आपके एनवायरनमेंट और CloudWatch के बीच परिवहन को आपकी गवर्नेंस और सुरक्षा आवश्यकताओं से मेल खाना चाहिए। सामान्य रूप से, AWS के बाहर वर्कलोड के लिए प्राइवेट endpoints का उपयोग सबसे कड़ाई से विनियमित उद्योगों के ग्राहकों की आवश्यकताओं को भी पूरा करता है। हालाँकि, अधिकांश ग्राहकों को हमारे पब्लिक endpoints द्वारा अच्छी तरह से सेवा दी जाएगी।

प्राइवेट endpoints का उपयोग​

Metrics और logs पुश करने के लिए, CloudWatch agent की CloudWatch और CloudWatch Logs endpoints तक कनेक्टिविटी होनी चाहिए। Agent कहाँ इंस्टॉल है इसके आधार पर इसे प्राप्त करने के कई तरीके हैं।

VPC से​

a. आप VPC Endpoints (CloudWatch और CloudWatch Logs के लिए) का उपयोग करके अपने VPC और CloudWatch के बीच EC2 पर चल रहे agent के लिए पूरी तरह से प्राइवेट और सुरक्षित कनेक्शन स्थापित कर सकते हैं। इस दृष्टिकोण से, agent ट्रैफ़िक कभी भी इंटरनेट से नहीं गुज़रता।

b. एक अन्य विकल्प पब्लिक NAT gateway है जिसके माध्यम से प्राइवेट सबनेट इंटरनेट से कनेक्ट हो सकते हैं, लेकिन इंटरनेट से अनचाहे इनबाउंड कनेक्शन प्राप्त नहीं कर सकते।

नोट

कृपया ध्यान दें कि इस दृष्टिकोण में agent ट्रैफ़िक तार्किक रूप से इंटरनेट के माध्यम से रूट होगा।

c. यदि आपके पास मौजूदा TLS और Sigv4 तंत्र से परे प्राइवेट या सुरक्षित कनेक्टिविटी की आवश्यकता नहीं है, तो सबसे आसान विकल्प हमारे endpoints तक कनेक्टिविटी प्रदान करने के लिए Internet Gateway का होना है।

ऑन-प्रिमाइसेस या अन्य क्लाउड एनवायरनमेंट से​

a. AWS के बाहर चल रहे agent इंटरनेट (अपने नेटवर्क सेटअप के माध्यम से) या Direct Connect Public VIF के माध्यम से CloudWatch पब्लिक endpoints से कनेक्टिविटी स्थापित कर सकते हैं।

b. यदि आपको आवश्यकता है कि agent ट्रैफ़िक इंटरनेट के माध्यम से रूट न हो तो आप AWS PrivateLink द्वारा संचालित VPC Interface endpoints का लाभ उठा सकते हैं, Direct Connect Private VIF या VPN का उपयोग करके प्राइवेट कनेक्टिविटी को अपने ऑन-प्रिमाइसेस नेटवर्क तक विस्तारित कर सकते हैं। आपका ट्रैफ़िक इंटरनेट पर एक्सपोज़ नहीं होता, खतरे के वेक्टर समाप्त हो जाते हैं।

success

आप AWS Systems Manager agent से प्राप्त क्रेडेंशियल का उपयोग करके CloudWatch agent के लिए अस्थायी AWS एक्सेस टोकन जोड़ सकते हैं।
