Amazon CloudWatch Omni の紹介

概要​

Amazon CloudWatch Omni は Amazon CloudWatch の次世代版です：AI を活用し、オープンスタンダード上に構築され、AWS コンソール外で提供される、再構想されたオブザーバビリティエクスペリエンスです。AI 時代のために設計された CloudWatch Omni は、AI エージェント、アプリケーション、インフラストラクチャのモニタリングを単一のソリューションに統合します。

Omni はオペレーター向けのスタンドアロン Web UI と開発者向けのネイティブ IDE 拡張機能の両方として提供されるため、コードをローカルで実行した瞬間にエージェントトレースが表示されます。OpenTelemetry 上に構築されています：既に CloudWatch に送信しているテレメトリは再設定なしで Omni に表示され、OpenTelemetry で計装した他のワークロードは OpenTelemetry Protocol（OTLP）エンドポイントにテレメトリを送信します。

Omni は CloudWatch 統合データストア上に位置するため、エージェントの動作をアプリケーションの健全性からインフラストラクチャまで接続します — エージェントの推論、古いナレッジベース、下流のレイテンシスパイクなど、真の根本原因を見つけることができます。

使用するタイミング​

シナリオを選択して、CloudWatch Omni がどのように適合するかを確認してください。

AI エージェントが実行中かどうかだけでなく、なぜそのような行動をしたかを知る必要がある。

Omni はエージェントに評価駆動のオブザーバビリティをもたらします — Strands、CrewAI、LangGraph、OpenAI Agents SDK、Vercel AI SDK にわたって、動作を観察し、品質を継続的に評価し、出荷前に修正を検証します。

AI エージェント、アプリケーション、インフラストラクチャを 1 か所で観察したい。

Omni は CloudWatch 統合データストア上に構築された単一のエクスペリエンスで 3 つすべてを統合するため、ツールを切り替えることなくエージェントの動作からアプリケーションの健全性、インフラストラクチャへと移動できます。

既に CloudWatch にテレメトリを送信しており、その上に AI ファーストのエクスペリエンスが欲しい。

既に CloudWatch に送信しているテレメトリは再設定なしで Omni に表示され、すべての調査は構築・メンテナンスしたダッシュボードではなく、自然言語の質問から始まります。

OpenTelemetry でワークロードを計装しており、ベンダーニュートラルな取り込みパスが欲しい。

Omni は OpenTelemetry 上に構築されています。計装したワークロードは OpenTelemetry Protocol（OTLP）エンドポイントにテレメトリを送信します — プロプライエタリなエージェントは不要です。

複数のアカウント、リージョン、クラウドにわたるシグナルを相関させる必要がある。

Omni は複数の AWS アカウントとリージョン、およびマルチクラウドソースからエージェントとアプリケーションのテレメトリを取り込みます — 現在 Azure から始まっています。

開発者が IDE 内でオブザーバビリティを必要とし、オペレーター向けの Web エクスペリエンスも必要。

オペレーターにはオフコンソール Web エクスペリエンスが、開発者には VS Code、Kiro、Cursor 向けのネイティブ IDE 拡張機能が提供され、コードをローカルで実行した瞬間にエージェントトレースが表示されます。

ガイダンス​

Amazon CloudWatch Omni は 5 つの機能に基づいています。各機能が何を提供するか、なぜ重要か、スキップした場合のトレードオフを確認するためにステップスルーしてください。

01

信頼できるエージェントを出荷する

単なるアップタイムではなく、評価駆動のオブザーバビリティ

Omni はエージェントの動作を観察し、品質を継続的に評価し、出荷前に修正を検証します — Strands、CrewAI、LangGraph、OpenAI Agents SDK、Vercel AI SDK にわたって。

Why it matters

エージェントは非決定的です。「実行中ですか？」は「正しいことをしていますか？」と同じ質問ではありません。継続的な評価は、アップタイムモニタリングが見逃す品質の退行をキャッチします。

Trade-off if you skip it

テレメトリではなく、お客様からエージェントの問題を知ることになります。

役割に合ったインターフェースを選択する​

CloudWatch Omni はオペレーターと開発者が作業する場所で対応します。

  • オペレーター（Web UI）
  • 開発者（IDE）

オペレーター向けに構築されたオフコンソール Web エクスペリエンスを通じて Omni にアクセスします：Omni スペース、アプリケーションマップ、サービス、ダッシュボード、アラート、評価ダッシュボード、およびガイド付き調査 — すべて AWS コンソール外で。

VS Code、Kiro、Cursor 向けのネイティブ IDE 拡張機能を使用します。コードをローカルで実行した瞬間にエージェントトレースが表示されるため、開発者はエディターを離れることなくエージェントの動作を観察・評価できます。

なぜ重要か： エージェントをローカルでデバッグする人と本番環境のインシデントをトリアージする人は、同じデータに対して異なるサーフェスが必要です。単一のインターフェースでのトレードオフ：2 つのオーディエンスのいずれか一方が常に不利な条件で作業することになります。

始めるためのサンプルアプリケーション​

自身のワークロードに Omni を向ける前に、2 つのリファレンスアプリケーションを探索するのに役立ちます。

エージェントとアプリケーション

Pet Adoptions

AWS One Observability Workshop の一部：EKS、ECS、Lambda にわたって実行される、ADOT/OTel SDK で完全に計装されたポリグロットマイクロサービスのペット養子縁組ストアです。

その Waggle AI アシスタントは、4 つのサブエージェントに委任する Strands オーケストレーターで、各サブエージェントは異なるフレームワーク（LangGraph、CrewAI、LlamaIndex、OpenAI SDK）と異なる Bedrock モデルで構築され、それぞれが AgentCore Gateway の背後にある独自の AgentCore Runtime としてデプロイされています。AgentCore Memory、Guardrails、Knowledge Base で補完され、エンドツーエンドでレスポンスがストリーミングされます。

GitHub で表示

アプリケーション

Open Telemetry Astronomy Shop デモ

アップストリームの CNCF OpenTelemetry リファレンスアプリ：10 以上の言語にわたる約 20 のマイクロサービスで構築された望遠鏡の e コマースストアで、すべてがトレース、メトリクス、ログのためにネイティブに計装されています。

Jaeger、Prometheus、Grafana、OpenSearch が同梱され、オンデマンドで現実的な障害を注入するフィーチャーフラグも備えています。ベンダーニュートラルな計装パターンと OTel データが CloudWatch Omni にどのように流入するかを示すのに最適です。

ヒント

まず Astronomy Shop で OpenTelemetry データが再設定なしで Omni にどのように流入するかを確認し、その後 Pet Adoptions に移動して複数のフレームワークにわたるエージェントレベルの評価駆動オブザーバビリティを探索してください。
